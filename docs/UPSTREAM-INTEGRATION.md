# 上游数据源集成边界

RelayBase 通过运行时配置的第三方数据源提供数据能力。公开仓库只包含通用代理、
计费、目录审核和安全控制逻辑，不保存或发布任何数据源的完整 OpenAPI 快照、
原始文档、来源哈希、官方标签清单或控制面路由。

## 目录策略

- API 市场只读取当前部署在管理后台完成同步、审核和核价的运行时目录。
- 未配置数据库、未成功同步或目录状态不一致时，市场返回空结果，不使用静态回退。
- 已恢复的运行时完整市场同时保留完整定义条目与 price-only 文档待同步条目。
  price-only 条目只存在于价格目录，尚未匹配到接口文档与 HTTP 方法，因此
  `method=null`、`documentationStatus=pending`，只能用于能力发现和客户价预设，
  不得调用或上架。
- 公共列表使用 RelayBase 自己的分类与说明，不返回数据源名称、来源地址、
  OpenAPI 版本、原始描述、原始 operationId 或快照哈希。
- 上游内部账户、凭据、价格和下载器等控制面路径不会进入客户市场。
- 参数结构只在运行时按安全策略过滤后展示；疑似 Cookie、会话、令牌、密钥、
  写入或互动能力的端点不能公开代理。
- 后台负责审核客户定价和上下架；同步只更新运行时证据与上游基础成本，不得静默
  覆盖管理员设置的客户价格或把新条目自动上架。
- price-only 条目只有在后续运行时文档提供匹配方法和输入定义，并经新一轮同步转为
  完整定义条目后，才能进入安全分类和人工上架流程。

## 运行时数据源

- 公开代码、部署模板和示例配置不保存固定来源地址或启动回退凭据。
- 运营方通过管理后台录入来源 HTTPS origin、API 前缀、文档/价格/凭据路由，并
  单独加密保存 API Key。
- `UPSTREAM_ALLOWED_ORIGINS` 仅作为托管 Secret 保存，列出后台可选择的精确
  HTTPS origin。留空、来源不在白名单或凭据验证失败时，同步与真实代理必须
  fail closed。
- 来源白名单、运行时来源记录和加密主密钥属于私有运营配置，不得通过市场 API、
  健康接口、日志或构建产物公开。

## 中性化迁移

- `0014` 会把旧来源标识改为中性标识，并永久撤销迁移前的全部托管凭据。
- 迁移会不可逆覆盖旧凭据密文和哈希、清除验证信息与活动凭据，并关闭托管模式；
  旧密钥不能通过代码回滚、数据库记录切换或重新激活恢复。
- 升级后必须先配置来源 Origin 白名单，再在管理后台保存运行时来源、重新录入并
  验证一条新凭据，随后执行完整目录同步和人工审核。

## 授权与生产门禁

去来源化不替代授权。启用真实代理、转售、缓存、价格加成或稳定币收款之前，运营方
仍须取得适用的书面商业授权和法律意见，并完成支付商 KYB、AML/制裁流程、客户条款、
隐私政策、支持渠道、监控、备份和定时对账。

这些证据应保存在受控的私有合规系统中，不应放入公开源码仓库。任一门禁缺失时，
RelayBase 必须保持安全沙盒并拒绝真实代理或充值。

## 发布纪律

公开发布前必须确认：

1. Git tree 不包含数据源派生目录、原始文档、来源哈希或生成器输入。
2. 测试只使用完全合成的数据和域名。
3. 公开市场在无运行时目录时返回空结果。
4. 当前发布分支的 Git 历史不包含曾经提交过的派生目录 blob。
5. README、变更日志和网站文案只描述 RelayBase 自有契约与通用运营要求。
